## 0. 基线管理

本文件与两份配套文件共同构成开发需求基线。产品行为以本文件为准，技术实现以技术架构为准，任务和验收以开发任务清单为准。后续确认的变更须修改对应文档、记录版本及原因，不以零散聊天覆盖基线。文中默认数值是已确认的初始运营建议，不是代码常量；设计示例不是已校验关卡或实际运营数据。尚需验证的事项见末节，不视为已经通过审核或测试。

## 1. 产品名称与定位（确认项 01）

| 项目 | 定义 |
|---|---|
| 中文名 | 格有趣 |
| 英文名 | GridFun |
| 宣传语 | 每一格，都有趣 |
| 产品定位 | 轻量休闲治愈型逻辑益智产品 |
| 开发目标 | 普通微信小程序，uni-app + Vue3 + TypeScript；同时支持 H5 调试 |
| 商业模式 | 微信官方广告为主，不充值、不提现 |
| 运营 | 自有服务器、数据库及独立管理后台，不使用微信云开发 |

目标是玩家专注推理、低挫败感，运营者通过后台持续增加内容和调整运营策略。目标物不绑定某种动物或角色。普通小程序发布类目、名称可用性、商标、广告资格仍须确认；不得以普通小程序技术形式规避游戏类目审核。

## 2. 核心玩法（确认项 02）

- N×N 棋盘划分为 N 个区域，区域以四邻接连续，每个格子恰属一个区域。首发 N=4、5、6、7、8、9、10。
- 玩家最终放置 N 个目标物：每行恰好一个、每列恰好一个、每区域恰好一个、任意两个目标物不得八邻接（含对角）。
- 合格关卡必须有且仅有一个解，尽量通过合理逻辑推理完成，不以猜测为正常玩法。
- 无生命限制、无失败次数限制、无强制倒计时；记录实际耗时但超过目标仍可继续。撤销、重置、基础辅助免费且不限次数。满足规则自动通关，不需提交按钮。
- 默认即时显示冲突；用户可关闭视觉反馈但不影响计错。广告不作为正常通关条件。

## 3. 游戏模式、关卡与星级（确认项 03）

### 3.1 游戏模式

| 功能 | 经典闯关 | 每日挑战 | 自由挑战 |
|---|---|---|---|
| 分配 | 所有玩家同一经典序列 | 每日同一谜题，北京时间 00:00 刷新 | 按棋盘规格和难度随机抽取 |
| 开放 | 从第 1 关开始，通关解锁下一关 | 完成或跳过新手教学后开放 | 首页进入，自选规格、难度 |
| 历史 | 可重玩 | 可补玩历史日期 | 优先未玩过的合格谜题 |
| 进度 | 独立存档 | 独立存档 | 独立存档 |
| 奖励 | 首通及新增历史星级 | 日期首次完成奖励 | 默认无金币奖励，可后台配置，防重复刷取 |
| 结算主操作 | 下一关 | 返回每日挑战 | 随机下一关 |

三种模式复用游戏页面、核心算法和结算组件。限时挑战、竞技、排行榜后续考虑。每日挑战记录本月完成数、连续完成天数及历史；历史补玩增加完成数，不补连续完成天数；后台可提前安排未来数月或一年。自由挑战仅展示已有合格关卡的规格/难度组合。

### 3.2 棋盘与难度

难度独立于尺寸，依据实际推理技巧、步骤及复杂度，而非仅按 N 分级。

| 等级 | 含义 |
|---|---|
| L1 新手 | 明显的确定位置 |
| L2 简单 | 基础行列及区域排除 |
| L3 普通 | 多区域组合推理 |
| L4 困难 | 复杂关联和组合排除 |
| L5 专家 | 多层逻辑推演 |

初步规格矩阵（须以算法产出验证为准）：4×4 L1–L2；5×5 L1–L3；6×6 L2–L4；7×7、8×8 L2–L5；9×9、10×10 L3–L5。经典关卡采用总体渐进、难易交替的曲线。

| 经典关卡序号 | 尺寸 | 难度 |
|---|---|---|
| 1–5 | 4×4 | 新手 |
| 6–15 | 4×4 | 新手、简单 |
| 16–30 | 5×5 | 简单 |
| 31–50 | 5×5、6×6 | 简单、普通 |
| 51–75 | 6×6、7×7 | 普通 |
| 76–100 | 5×5 至 8×8 | 普通、困难 |
| 101+ | 6×6 至 10×10 | 混合 |

上述为初始编排建议，不是固定代码。章节轻量组织关卡，不增加星级门槛。初始可每 50 关一章，名称、封面、顺序、数量及推荐主题后台配置；示例初见方格、奇妙花园、森林漫步、蔚蓝海岸、星空漫游。关卡资源库与经典序号及每日日期映射独立。

首发目标 1000 道合格谜题：新手 50、简单 250、普通 350、困难 250、专家 100。质量优先，数量不是强制上线门槛；不能降低校验标准凑数。长期无固定关卡总量上限。

### 3.3 星级评价（核心不可变约束）

- 每关最高三星，通关必得一星；两项附加规则各独立奖励一星，未通关不得星。
- V1.0 支持 `completion`、`duration`（秒数 ≤ 阈值）、`errorCount`（次数 ≤ 阈值）。每关生成时独立设置，支持批量模板，发布前可调整并校验。
- 未来可扩展提示、撤销、操作次数、独立完成、一次通关、组合条件；首发不实现这些额外规则，但记录相应指标并预留规则处理器和版本。
- 规则结构包含 `type`、`operator`、`value`、`stars` 及 `ruleVersion`；发布时永久锁定棋盘、答案、难度、评价参数及判定版本，不得通过下架或退回草稿绕过。
- 例：120 秒以内且错误不超过 2 次可三星；只达到其中一个附加条件则二星；超过两项目标仍可一星通关。各关阈值不是全局固定值。
- 一星即可解锁下一关；重玩保留历史最高星级，最佳耗时独立记录；新增历史星级才增加累计星星及对应金币奖励，历史成绩不因新规则或模板变化重算。

```json
{
  "maxStars": 3,
  "ruleVersion": 1,
  "starRules": [
    {"type":"completion","stars":1},
    {"type":"duration","operator":"lte","value":120,"stars":1},
    {"type":"errorCount","operator":"lte","value":2,"stars":1}
  ]
}
```

## 4. 游戏操作及交互（确认项 04）

| 项目 | 规则 |
|---|---|
| 格子状态 | 空白、手动排除、目标物；冲突/提示/自动排除为附加效果 |
| 默认操作 | 工具模式：排除、放置两个工具，点击切换目标状态 |
| 可选操作 | 单击循环：空白→排除→放置→空白；首发不实现双击模式 |
| 滑动 | 排除工具下从空白开始批量标记，从排除格开始批量清除；单手势每格只处理一次，跳过目标物，不支持批量放置 |
| 撤销 | 一次点击或一次完整滑动视为一个操作；无限免费；不回退错误计数 |
| 自动排除 | 默认开启，可关闭；根据已放置目标物实时计算，浅色标记与手动深色标记分离 |
| 冲突 | 默认即时红框，可关闭显示，不影响实际计错 |
| 计错 | 每次新增目标物违反任意核心规则计一次，同时违反多条仍一次；与标准答案不同但暂无冲突不计错；手动排除错误、清除、自动排除不计错 |
| 重置 | 二次确认，清空本次棋盘、耗时、错误计数；不扣体力；保留历史最高成绩 |
| 暂停 | 隐藏棋盘，停止计时；恢复后继续 |
| 生命周期 | 返回首页、微信切后台、锁屏自动暂停并保存；广告及奖励处理期间暂停计时、隐藏棋盘 |
| 断网 | 已加载关卡可继续，本地记录待同步；正式成绩与资产由服务端校验 |

提示 V1.0 提供正确位置提示、已放错目标物纠正提示；高级逻辑解释、分步推理提示后续实现，不提供整关自动完成。使用提示默认不影响首发星级。提示服务失败不得消耗权益；具体原子扣减和恢复见架构。游戏记录耗时、错误、完成、提示、撤销、操作、自动辅助使用、暂停时长、重置、棋盘及必要操作历史。

结算展示本次星级、每条评价达成情况及实际成绩、历史最高星级、金币奖励及可选广告额外奖励；下一关/重新挑战/返回入口按模式展示。游戏过程中不展示底部导航和无关活动入口。

## 5. 体力、金币、星星与奖励（确认项 05）

初始运营参数如下，均可后台配置、校验、发布、版本化。体力系统首发启用但可整体关闭。金币仅游戏内获得，不支持人民币充值、交易或提现。星星是不可消耗的成绩指标，不是货币。

### 5.1 体力

| 参数 | 默认值 |
|---|---:|
| 新用户体力 / 自然恢复上限 | 30 / 30 |
| 自然恢复 | 每 5 分钟 1 点 |
| 经典新关卡 / 自由挑战 | 1 点 / 1 点 |
| 每日挑战 / 历史重玩 / 重置 / 恢复存档 | 0 点 |
| 广告补充 | 10 点/次，3 次/日 |

服务器时间计算离线恢复，达到自然上限停止；额外奖励可超过自然上限，实际持有硬上限默认 300、后台可配置；奖励超出部分暂存待领取，不丢失；无法获得体力时不提供体力广告入口。体力不足仍可等待、重玩或玩每日挑战，广告非强制。

### 5.2 金币与提示

| 参数 | 默认值 |
|---|---:|
| 新用户金币 | 100 |
| 经典首次通关 | 20 |
| 每新增一颗历史星 | 5 |
| 每日挑战首次完成 | 50 |
| 金币兑换提示 | 30/次 |
| 每日免费提示 | 3 次，次日刷新不累计 |
| 广告提示 | 1 次/完整观看 |
| 普通/高级主题示例 | 200/500 金币 |

首次通关奖励和新增历史星奖励分开计算。例如首次二星得 30 金币，再得二星无奖励，重玩三星新增 5 金币。每日免费提示优先，再使用签到等已获永久提示权益，之后由玩家主动选择金币或广告，不自动扣币或播放广告。撤销、重置、自动排除、冲突提示免费。

### 5.3 签到

北京时间 00:00 刷新，每日主动领取一次，七日循环；漏签保留进度、不补签、不自动签到。默认示例：D1 20 金币、D2 5 体力、D3 30 金币、D4 10 体力、D5 50 金币、D6 2 次提示、D7 100 金币+10 体力。支持组合奖励、可选广告翻倍、后台动态配置。

### 5.4 资产一致性

用户资产服务端权威，所有变动有流水，事务及唯一业务键防重复。开始挑战绑定适用奖励配置版本，结算按绑定版本，已发放历史奖励不重算。后台补发需原因、审计和二次确认，不允许直接改余额。不同模式共享谜题时奖励与累计星星的具体去重维度须在数据库/API详细设计中明确，禁止重复刷取。

## 6. 主题及收集（确认项 06）

主题与关卡、算法、评价、难度完全解耦；全部模式使用玩家当前主题，章节可推荐但不强制。已解锁永久拥有、自由切换、换手机可恢复；主题下架原则上不影响已拥有权益。主题更新采用版本，解锁条件可改但不能重新锁定既有权益。

| 首发主题（美术名称可定稿） | 目标物 | 初始解锁示例 |
|---|---|---|
| 经典星光 | 金色星星 | 默认免费 |
| 森林物语 | 蘑菇 | 200 金币 |
| 水果乐园 | 草莓 | 200 金币 |
| 深海漫游 | 鲸鱼 | 累计 100 星 |
| 星空秘境 | 小星球 | 完成第 50 关 |
| 宝石世界 | 宝石 | 500 金币 |

首发支持免费、金币、累计星星、通关进度、广告进度解锁；未来扩展签到、每日挑战、活动、组合条件。主题页提供浏览、预览、解锁、使用、收藏进度。后台配置名称、封面、目标物、背景、区域配色（至少 10 色）、排除标记、圆角、主色、文字、冲突色、解锁规则、排序、版本及上下架，实时预览不同尺寸。专属动画、音乐、音效预留。首发不做养成、家园、装备、碎片、盲盒、有效期、充值和交易。

## 7. 广告变现（确认项 07）

激励视频为主要方式，插屏功能实现但首发默认关闭；暂不实现 Banner、原生模板、开屏及第三方广告平台。正式播放依赖微信广告权限和有效广告位，未开通时自动隐藏，游戏仍可正常运行。

| 激励场景 | 默认奖励 | 每人每日上限 |
|---|---|---:|
| 获取提示 | 1 次提示 | 10 |
| 补充体力 | 10 点 | 3 |
| 通关奖励 | 本次金币 ×2（额外追加原奖励） | 5 |
| 签到奖励 | 基础奖励 ×2 | 1 |
| 每日挑战 | 额外 50 金币（示例） | 1 |
| 主题解锁 | 进度 +1 | 5 |

全局激励上限 20 次/日，建议冷却 30 秒；全局和场景限制同时生效。开放关卡、奖励、倍率、广告位、次数、间隔、生效时间均后台配置。广告位与业务场景分离；同一广告位可关联多个场景。

插屏默认策略：前 20 关保护，每完成 5 关、结算结束后才触发，最短间隔 180 秒、每日最多 5 次、激励视频后保护 180 秒；禁止启动或游戏中突然展示、禁止连续弹出。实际策略必须遵守平台最新规范。

用户主动观看激励视频；基础奖励通关后自动到账，广告只追加，不翻倍星级。无金币奖励不显示通关翻倍。播放失败、提前关闭不发额外奖励且不扣基础权益。完整观看后断网允许合法待领取恢复。会话锁定奖励版本、身份、有效期、状态，后端幂等发放及流水；客户端 `isEnded` 不是独立可信的收入或反作弊证明。全局紧急关闭阻止新会话，已完成合法领取继续处理。

三种运行模式：MOCK（仅开发测试）、DISABLED（未开通/关闭）、LIVE（正式权限）；生产禁止模拟发奖。统计点击、请求、加载、播放、完成回调、领取、异常；官方曝光、eCPM、收益、结算以微信官方报表为准。首发支持手动录入/导入，自动同步待确认官方接口能力。共享广告位不得凭空拆分各场景实际收益。

公共组件：导航、按钮、卡片、棋盘、工具栏、暂停、重置/退出确认、提示、体力不足、金币不足、奖励领取、主题解锁、广告状态、加载/异常、公告/更新、隐私确认。

## 10. 技术架构（确认项 10）

最终客户端为 uni-app + Vue3 + TypeScript，普通 View/Flex 动态样式实现棋盘，不采用 Canvas 或游戏引擎。后台 Vue3/TS/Element Plus/UnoCSS/Pinia/ECharts/Vite，后端 Node.js/Fastify/SQLite WAL/Drizzle，独立纯 TS 核心算法，Yarn Workspaces 单仓库、Worker、Docker Compose/Nginx。使用自有阿里云 ECS 2 核 2GB/40GB/3Mbps。详细设计见 [技术架构文档](02-technical-architecture.md)。

## 12. 开发计划与验收（确认项 12）

采用准备阶段 00 及阶段 01–08，逐步交付。先算法，再最小可玩闭环，后端及后台联通，再完整业务、UI、广告、测试部署、平台发布。详细任务、里程碑、验收和职责见 [开发任务清单](03-development-plan.md)。首发不包含充值、社交、排行榜、复杂养成、成就、限时挑战、高级逻辑提示；候选后续路线不属于首发承诺。

## 13. 未决事项与明确边界

以下是详细设计或外部验证任务，不是已确认的新产品规则：

## 14. 2026-11-25 已确认详细口径

- 历史每日挑战补玩增加完成数，不补连续完成天数。
- 自由挑战默认不奖励金币，允许后台配置。
- 三模式成绩独立；累计星星按用户与谜题的跨模式历史最高星计算，同题重复完成不重复累计。例：经典二星、每日同题三星，累计贡献由2增至3，而非5。
- 本次确认未扩展到跨模式金币奖励去重，相关口径仍待细化。当前没有正式业务数据，无需数据迁移；后续实现应在结算事务内更新谜题最高星及累计差值。

## 15. 2026-11-25 第二组确认

- 签到获得的提示次数永久保留；先消耗每日免费次数，再消耗永久提示权益，最后由玩家主动选择金币或广告。
- 跳过教学后允许进入每日挑战；仍可重看教学。
- 重置不扣体力，清空本次棋盘、操作历史、耗时和错误等本次指标，保留历史成绩及开始挑战时绑定的奖励配置。具体会话/attempt结构属于技术实现，不改变上述行为。
- 当前无正式业务数据，无需迁移；涉及提示扣减顺序、每日挑战开放校验、重置及结算测试。

## 16. 2026-11-25 第三组确认

- 体力持有硬上限默认300，可后台配置；奖励超额部分暂存待领取，不丢失。无法获得体力时不提供体力广告入口。
- 跨设备存档冲突保留两份，由玩家选择继续哪份，不自动覆盖。
- 异常关卡替换保留历史成绩，旧存档归档；进入替代关卡不重复扣体力，不重复发放已经领取的奖励。
- 数据设计需覆盖待领取权益与幂等领取、存档冲突副本与选择版本、关卡替换映射及原奖励归属。当前无正式业务数据，无需迁移。

## 17. 2026-11-25 第四组确认

- 广告会话创建后30分钟内完成观看，完成后24小时内可恢复领取。此为已确认业务时限；平台完成凭证、断网恢复及时间可信性仍须验证，客户端完成回调不能单独作为可信凭证。
- 经典首通金币按经典关卡序号去重，每日金币按挑战日期去重，两类分别发放。
- 同题跨模式新增星级金币仅按用户与谜题的历史最高星增长发放一次，不因切换模式重复获得。
- 自由挑战默认无金币；后台开启完成奖励时，同一用户对同一谜题仅首次完成发放，重玩不重复。开启配置前已有完成记录如何处理仍需细化，不默认补发。
- 涉及奖励唯一键、结算事务及广告恢复校验；当前无正式数据，无需数据迁移。
