# 格有趣（GridFun）｜开发任务清单与验收标准

- 版本：1.0.0｜2026-11-24
- 状态：计划已确认；以下任务均尚未完成，不代表已创建工程或通过验收
- 关联：[产品需求规格书](01-product-requirements.md) · [技术架构](02-technical-architecture.md)

## 0. 执行约定

本清单与另外两份文档共同作为正式开发唯一需求基线。任务编号用于 Git issue、提交、测试报告、验收和变更追踪。每个阶段交付可运行成果、源码、测试和已知问题，不提前宣称实际测试成功。P0 为首发必需，P1 为计划首发完善项；P1 如延期需要用户确认，不能无声删减。阻塞项未解决不得宣称正式上线。开发过程中发现未决产品规则，应先记录并确认，不擅自修改已确认需求。

工作量占比建议：准备 5%、算法 15%、操作 10%、后端后台 20%、完整业务 20%、UI 素材 15%、广告运营 5%、测试部署 10%。非工期或未来自动交付承诺。阶段内部可并行，但不能绕过依赖及发布门槛。

| 棋盘操作响应 | P95 ≤50ms | 10×10 点击和滑动样本 |
| 普通 API | P95 ≤300ms | 记录负载、端点、数据规模 |
| 通关结算 API | P95 ≤500ms | 包含事务、并发场景 |
| 基础动画 | 尽量接近 60 FPS | 真机测量，不阻塞交互 |
| 压测错误率 | <0.1% | 排除预期业务拒绝需明确口径 |
| 稳定性 | 至少 24 小时 | 日志、内存、磁盘、数据库 |
| 生成 Worker | 默认 1 个 | 并行 API 延迟及资源监控 |

如目标不能达到，记录实测、瓶颈和优化方案，任何验收指标变更需确认。2 核 2GB/3Mbps 不代表固定可承载用户数。

## 12. 缺陷红线及变更管理

P0 阻塞：无法进入/通关、无解/多解、资产丢失/重复、数据泄露/越权、数据库无法恢复、已发布规则可非法修改、严重广告奖励异常、平台类目不符。P1 严重：核心界面明显错位/频繁卡顿、进度无法恢复等。P0/P1 严重缺陷上线前全部解决。此处缺陷等级与任务优先级是不同概念。

每个任务完成应记录：任务 ID、版本/提交、交付物、测试结果、未完成项及验收意见。需求变更写明日期、原规则、新规则、原因、影响模块、迁移/兼容策略及确认状态；已发布关卡不可变要求不得被普通运营配置变更绕过。
