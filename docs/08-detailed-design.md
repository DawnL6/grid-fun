# S00-07 数据、接口与业务详细设计

状态：草稿，未冻结；产品待决项未确认前不视为S00-07完成。依据01/02/03基线；本文不代表已实现业务接口。日期2026-11-25。

## 数据约定与迁移

主键使用服务端生成的不透明字符串；金额/金币/体力使用整数，时间存UTC毫秒，业务日期由Asia/Shanghai生成YYYY-MM-DD。所有外键连接启用foreign_keys；资产余额非负；正式成绩最高星级0–3。JSON列验证json_valid，结构由接口Schema再次校验。

41张候选表继续按架构分模块实施，不以空表冒充完整DDL。阶段03使用Drizzle schema生成版本化SQL；版本表记录编号、校验和、执行时间；已执行迁移不得修改。迁移前一致性备份，维护窗口执行短事务，失败回滚。先在空库和前一版本副本验证，再允许生产升级。代码回退要求数据库向后兼容，否则恢复经验证的一致性备份，不自动运行破坏性down迁移。

## 请求、权限与幂等

接口前缀/api/v1，管理员独立/admin。玩家JWT必须同时验证服务端会话未撤销，访问资源须校验归属；管理员令牌独立audience。登录接口不要求已有令牌，其余默认认证。响应使用requestId用于追踪，不记录code、token、AppSecret。

列表limit默认20，最大100；cursor使用不透明游标，稳定排序created_at,id。日期区间端点均含边界，最大跨度由端点规定。错误体为code/message/requestId/details；400参数错误、401未认证、403无权限、404资源不存在、409状态/版本冲突、422业务条件不满足、429限流、503依赖不可用。

开始游戏、提示、结算、签到、主题解锁、广告领取、后台补发使用Idempotency-Key。作用域为主体+操作+key；保存请求摘要和确定响应。同key不同请求返回409；同key已成功返回原响应。禁止使用客户端key代替业务唯一键：签到仍按日期去重、结算仍按尝试去重、广告仍按会话去重。事务失败不得落下成功记录。保留期限及过期重试策略仍需按业务细化。

## 关键事务

开始：验证模式/context、开放条件、已发布关卡 → 结算体力恢复 → 检查余额 → 原子扣体力、写流水、创建绑定版本会话。事务中不请求微信或运行长算法。

存档：WHERE session_id=? AND version=?更新，成功version+1；影响行数0返回409及服务器版本，不自动覆盖。离线操作保留本地副本；用户冲突选择策略见待决项。

结算：验证归属/尝试状态 → 独立验证四规则及回放指标 → 在短事务中重新确认状态 → 插入唯一成绩 → 更新历史最大星和独立最佳耗时 → 发奖励及流水 → 写确定响应。所有写入同一事务，重复提交不重复发奖。

提示：先在事务外计算有效提示，再在事务内复核存档版本和权益，写提示结果、扣减与幂等响应；若棋盘已变返回409且不扣。网络丢失响应可用同key恢复结果。

配置发布：草稿校验 → 显示差异 → 发布新版本并更新当前指针、审计；恢复旧配置复制成新版本。进行中会话继续使用绑定快照，紧急广告开关只阻止新会话。

## 配置分类

服务器环境：密钥、数据库路径、NODE_ENV，不进入运营后台或客户端。

运营版本：体力恢复周期/上限/消费、金币奖励、提示、签到七日奖励、广告次数/冷却/场景、主题条件。采用基线默认值；未决数值不填生产默认。

关卡冻结：尺寸、区域、答案、难度、starRules、ruleVersion、生成器与校验版本。与运营配置分开，不允许配置恢复绕过锁定。

## 后续交付门槛

仍需完整DDL草稿、字段级OpenAPI、配置Schema及契约/约束测试；本稿先固化事务边界与待决清单，不将其冒充完整S00-07交付。产品口径确认后才能冻结相关索引、唯一键和奖励语义。

### 已确认口径的数据设计影响

增加user_puzzle_progress，主键(user_id,level_id)，best_stars限制0–3。三模式progress保留各自成绩。结算事务读取并更新谜题最高星，累计贡献仅取max(旧值,本次星)-旧值；并发结算串行比较，不从三个模式表直接相加。每日连续天数按实际完成日与挑战日期匹配的当日完成记录计算；补玩只影响对应日期完成状态和完成数。

### 第三组确认的数据设计影响

待领取体力独立于实际余额存储，记录来源唯一键、总额、已领取额及剩余额；在短事务内按可用容量领取，余额与待领取额同时更新，重复请求不重复到账。存档冲突副本保存来源设备、基准版本与完整棋盘/指标，选择时再次比较服务器版本，旧选择不得覆盖新存档。关卡替代保留旧映射、原挑战扣费依据及奖励业务归属，历史记录继续引用旧关卡；服务端检查替代资格，不能仅相信客户端免费标记。以上待完整DDL及接口契约落地验证。

### 第四组确认的数据设计影响

奖励业务键按主体隔离：classic:first:{sequence}、daily:first:{date}、free:first:{levelId}；新增星级按star:{levelId}:{starOrdinal}逐颗去重，最高星更新与金币/流水同事务。结算不从单模式最高星推算跨模式增量。经典与每日完成奖励彼此独立。自由奖励开关变化前已有完成记录的资格仍需明确，不默认为补发。广告保存created_at、completion_deadline、可信完成时间及claim_deadline，过期检查由服务器执行；如何取得可信完成依据留待平台验证，不以客户端时间规避期限。
